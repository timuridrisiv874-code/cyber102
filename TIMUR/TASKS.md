# Задачи Тимура

## День 1 — проверить текущий прототип

1. Запустить приложение на ноутбуке и пройти проверки API и тестов из [чек-листа](CHECKLIST.md). Через паспорт `P-102` показать сценарий с несколькими выводами и запись с заметкой в журнале.
2. Открыть один HTTPS-адрес на iPhone в Safari и на Android в WebView. С участником 3 проверить Basic Auth, системное разрешение `CAMERA` и выдачу `RESOURCE_VIDEO_CAPTURE` через `WebChromeClient.onPermissionRequest` для доверенного HTTPS-origin. Зафиксировать устройства, версии ОС и WebView, сеть и результаты. [Проверка с телефонов](../docs/operations/deployment.md).
3. Проверить QR, повторную съёмку, отказ в доступе к камере и понятный ответ на непригодный кадр. Подготовить встроенный пример для показа интерфейса.

## День 2 — связать этапы осмотра

1. Сохранить выбранный по QR или вручную насос при переходе к камере. Дать оператору выбрать компонент, подтвердить или исправить наблюдение. Привязать рамку к идентификатору и размерам зафиксированного кадра.
2. Согласовать с участником по данным контракт признаков. Показать в карточке наблюдение камеры, данные датчиков и вывод правил отдельными полями. Отсутствующие и просроченные показания отображать как неизвестные. [Контракт интеграции](../docs/research/chapters/integration-contract.md).
3. Добавить путь сохранения реального осмотра с серийным номером, временем, подтверждёнными признаками и выводами. Повтор с тем же `requestId` должен возвращать одну запись. Исходный кадр по умолчанию остаётся в памяти. Текущий `POST /api/history` сохраняет демонстрационные сценарии. [Текущий контракт БД и API](../docs/architecture/database.md).
4. Проверить на двух устройствах связку «QR → насос → кадр → результат → запись». Если к показу готов только существующий журнал, показать сохранение на демонстрационном сценарии и указать это в протоколе. [Сценарий чекпоинта](../docs/checkpoints/checkpoint-1.md).
