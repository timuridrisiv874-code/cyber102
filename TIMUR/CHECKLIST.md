# Проверка вебки и API

## На ноутбуке

Запустите из корня репозитория в первом терминале.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m server.app
```

Из корня во втором терминале выполните проверки.

```sh
curl -fsS 'http://127.0.0.1:8000/api/health'
curl -fsS 'http://127.0.0.1:8000/api/diagnose?serial=P-102&scenario=multiple_findings'
curl -fsS 'http://127.0.0.1:8000/api/history?serial=P-102'
.venv/bin/python -W error -m unittest discover -s tests -v
```

- [ ] `/api/health` вернул `status: ok`. Сценарий вернул выводы об утечке, защитном кожухе, смазке или износе подшипника и регламентном ТО. Тесты прошли.
- [ ] В [локальном интерфейсе](http://127.0.0.1:8000/) сохранён результат сценария с заметкой. После обновления страницы запись отображается в журнале.

## На телефонах

На обоих телефонах откройте [HTTPS-стенд команды](https://cyber102.94.41.87.102.sslip.io/). Локальный адрес `127.0.0.1` выше используется на ноутбуке. Для каждого устройства заполните отметки после проверки.

| Проверка | iPhone Safari | Android WebView |
| --- | --- | --- |
| Вход по учётным данным команды | ☐ | ☐ |
| Отказ в разрешении камеры и повторная выдача | ☐ | ☐ |
| Задняя камера, поворот экрана и возврат из фона | ☐ | ☐ |
| «Проверить кадр», карточка и рамка на зафиксированном кадре при обнаружении признака | ☐ | ☐ |
| «Новый кадр» убирает старую карточку и рамку | ☐ | ☐ |
| Непригодный кадр или сбой анализа даёт понятное сообщение | ☐ | ☐ |
| QR открывает паспорт `P-102`, неизвестный номер даёт сообщение об ошибке | ☐ | ☐ |
| Демонстрационный сценарий сохраняется с заметкой и виден после обновления | ☐ | ☐ |

Запишите дату, модель телефона, версию ОС, версию Safari или WebView, тип сети, время ответа и фактический результат. [Протокол приёмки](../docs/research/chapters/acceptance-and-roadmap.md).
