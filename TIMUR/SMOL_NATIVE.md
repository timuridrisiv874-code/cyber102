# Нативный SmolVLM на Android

Используется настоящий CPU-инференс через llama.cpp/libmtmd, без HTTP-сервера на телефоне. JNI-библиотека `cyber_smol` загружает два локальных GGUF: языковую часть SmolVLM2-2.2B-Instruct Q4_K_M и соответствующий visual projector Q8_0. Это выбранная конфигурация с приоритетом возможностей модели; скорость конкретного Redmi измеряется отдельно. Весов в Git нет.

Веса вместе занимают 1 705 125 856 байт (около 1,71 ГБ). Это размер файлов, не измерение потребления RAM. Модель не обучена на размеченных дефектах проекта; английское наблюдение является предварительным. Из ответа не создаются вымышленные рамки, показания датчиков, остаточный ресурс или подтверждённый диагноз.

## Подготовка и сборка

```sh
python3 android/app/src/main/cpp/fetch_llama.py
```

Скрипт скачивает только закреплённый архив, сверяет SHA-256 и распаковывает в игнорируемый `var/native/`. При наличии подготовленного исходника сеть не нужна. Native CMake принимает `LLAMA_CPP_DIR`; ревизия должна совпасть с маркером `CYBER102_REVISION`.

Android: NDK 28.2.13676358, CMake 3.22.1+, ABI `arm64-v8a`, API 26+. Сборка CPU использует базовый ARMv8-A/NEON: наличие dotprod, i8mm или SVE не предполагается. Native CMake принудительно использует Release для движка и зависимостей даже в debug APK; итоговая shared library запрашивает выравнивание страниц 16 КБ. HTTP, серверные утилиты, subprocess, FFmpeg, GPU и загрузчики моделей в нативную цель не включаются.

Для Mac/Linux можно собрать тот же движок с CLI:

```sh
cmake -S android/app/src/main/cpp -B /tmp/cyber-smol-host -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/cyber-smol-host --target cyber-smol-cli -j2
/tmp/cyber-smol-host/cyber-smol-cli MODEL.gguf MMPROJ.gguf IMAGE.jpg
```

Аргументы после изображения: текст инструкции, максимум генерируемых токенов, задержка отмены в миллисекундах. CLI нужен для проверки загрузки, изображения, генерации и отмены. Скорость Mac не переносится на Redmi; измерять телефон отдельно.

## Контракт JNI

`SmolNative`:

- `isAvailable()` — native library действительно загружена.
- `beginOperation()` — запоминает номер отмены до постановки задачи в очередь.
- `load(modelPath, projectorPath, threads, epoch)` — загрузка локальных файлов; 2–4 CPU-потока.
- `analyze(imagePath, prompt, maxTokens, epoch)` — JSON с `text`, `promptMs`, `generateMs`, `totalMs`, `inputTokens`, `generatedTokens`, `cancelled`.
- `cancel()` — неблокирующий запрос отмены.
- `unload()` — освобождение модели после завершения текущей операции. Для остановки текущей операции сначала вызывается `cancel()`.
- `isLoaded()` — неблокирующий флаг готовности.

Загрузка/анализ/выгрузка сериализованы в native engine; Java-менеджер также выполняет их на выделенном executor. UI не должен вызывать блокирующие операции на главном потоке. Модель остаётся в памяти между кадрами; KV-контекст очищается перед каждым изображением и после ответа, чтобы предыдущий снимок не влиял на новый.

Границы: контекст 2048 токенов, batch 256, генерация 1–128 токенов, пользовательская инструкция до 2000 байт. Рекомендуемый бюджет интерфейса 48–64 токена. Native принимает нормализованные JPEG/PNG до 3 МБ и до 1280 px по стороне; Android должен предварительно уменьшать кадр до 512–768 px. Отмена может сработать во время загрузки, visual encoding и декодирования; частичный ответ с `cancelled=true` не является законченным анализом.

Фиксируется специальный chat template SmolVLM из закреплённой библиотеки. Температура/случайное сэмплирование не используются: генерация greedy, что упрощает повторяемость проверки.

## Проверка настоящих весов и выбор размера

На Mac выполнена загрузка реальных GGUF, обработка изображения, отмена во время visual encoding, повторная обработка после отмены, повторный кадр без перезагрузки весов и выгрузка. Это проверка общего C++-движка. APK, Android ABI, расход батареи и скорость конкретного Redmi проверяются отдельно.

Для сравнения использованы 4 CPU-потока, 48 выходных токенов и одинаковый простой английский вопрос: `What is the main object in this image? Describe its color and visible surface.` Один проход по трём иллюстрациям оборудования и белому контрольному кадру, веса остаются в памяти. У эталонных иллюстраций нет верифицированной разметки дефектов; один предоставленный пример имеет watermark генеративной модели. Эти примеры проверяют работоспособность и характер ответа, а не точность промышленной диагностики.

| Проверка | SmolVLM 256M Q8 | SmolVLM 500M Q8 |
|---|---|---|
| Демонстрационный насос | «blue colored machine», 2,43 с | «blue-green colored pump», 3,55 с |
| Предоставленная иллюстрация насоса | «oil pump», 6,01 с | «blue-colored water pump», 8,07 с |
| Ржавое основание и болты | «metal object with rusted parts», 3,53 с | Описал металлическую конструкцию, болты и ржавчину, 6,55 с |
| Белый кадр | «white surface», 1,51 с | Придумал прямоугольный объект, 2,63 с |
| Максимальный RSS процесса на Mac | 492 МиБ | 877 МиБ |
| Общий размер двух GGUF | около 279 МБ | 545,6 МБ |

Указанные секунды — одиночные измерения Mac с другими запущенными процессами, а не гарантированная задержка телефона. Обе малые модели добавили неподтверждённый тип перекачиваемой жидкости: `oil` / `water`. У 500M описание отдельных предметов лучше, но отрицательный контроль хуже, файлы почти вдвое больше и ответы медленнее. Эти варианты сравнивались как компактные альтернативы; затем по требованию приоритета мощности выбрана 2.2B. Вывод любой из моделей показывается как предварительное наблюдение, не как диагноз.

Дополнительная проверенная модель: [официальный SmolVLM-500M-Instruct-GGUF](https://huggingface.co/ggml-org/SmolVLM-500M-Instruct-GGUF/tree/72e986006ef53e37cdd3f6d4241c90b0f01df376), revision `72e986006ef53e37cdd3f6d4241c90b0f01df376`. SHA-256 языкового Q8 файла `9d4612de6a42214499e301494a3ecc2be0abdd9de44e663bda63f1152fad1bf4`; projector Q8 `d1eb8b6b23979205fdf63703ed10f788131a3f812c7b1f72e0119d5d81295150`. Эта пара скачана в игнорируемую `var/models/smolvlm500/` для сравнения и не включается в APK автоматически.

Повторяемый smoke и сравнительный harness:

```sh
cmake --build /tmp/cyber-smol-host --target cyber-smol-smoke cyber-smol-benchmark -j2
/tmp/cyber-smol-host/cyber-smol-smoke MODEL.gguf MMPROJ.gguf IMAGE.jpg
/tmp/cyber-smol-host/cyber-smol-benchmark MODEL.gguf MMPROJ.gguf IMAGE1.jpg IMAGE2.jpg
```

`cyber-smol-benchmark` принимает до пяти кадров и выводит JSON со всеми ответами, временем загрузки, временем каждого кадра и пиковым RSS. Для Android эти цифры нужно получить непосредственно на устройстве.
