# Cyber102 0.8 на Redmi

Проверено на Redmi 2606FRN72Y, Android 16, MediaTek MT6769V/CZ, ARM64, 8 ГБ RAM. Телефон был в авиарежиме с выключенным Wi-Fi. Тест выполнял настоящий инференс с локальными GGUF SmolVLM2 2.2B. Использован лёгкий APK с тестовой подписью ноутбука; DEX и манифест весов совпали с серверной сборкой. Полный опубликованный APK собран и проверен на Windows-сервере 3090.

| Проверка | Результат |
|---|---|
| Чтение настроек | 0,4–0,6 мс на `Cyber102-prefs` |
| Запись настроек | 5,3–8,5 мс на `Cyber102-prefs` |
| Загрузка JNI | 28–78 мс на `Cyber102-smol` |
| Подготовка ранее скопированной модели | 11,4–20,3 с на `Cyber102-smol` |
| Ручная отмена | 790 и 801 мс до готовности интерфейса. Повторный расчёт после первой отмены стартовал |
| Первый полный анализ | Не завершился за лимит 180 с. Приложение остановило расчёт и вернулось в готовое состояние |
| ANR | В записанных трассах не найдено события ANR для Cyber102 |

В первом прогоне Perfetto зафиксировал 180,39 с в фоновом расчёте. Это ограничение скорости текущей модели на этом устройстве. В прогонах отмены JNI-сигнал на главном потоке занимал не более 0,17 мс. Цифры получены в двух прогонах и относятся к этому устройству и тестовому кадру.

Трассы записаны официальным [android-profiler](https://github.com/android/skills/tree/5815d27fda564aa9f07ebdcb5e57ed3e8d904e0d/profilers/android-profiler) через `record_android_trace` и разобраны Perfetto Trace Processor. Системные трассы остаются в локальном `var/profiles/`, поскольку содержат системные события телефона.

С установленными совместимо подписанными APK приложения и теста, подготовленными локальными весами и выключенной связью запустить проверку двух отмен:

```sh
adb shell am instrument -w -r -e cancelOnly true \
  -e class ru.cyber102.app.OfflineInferenceTest \
  ru.cyber102.app.test/androidx.test.runner.AndroidJUnitRunner
```

Для проверки полного ответа и сохранения наблюдения запустить тот же тест без `cancelOnly`. Критерий успеха включает появление результата после отмены, поэтому на указанном Redmi эта проверка сейчас падает по тайм-ауту.

Для следующего сравнения на одном телефоне использовать одинаковые кадры клемм, муфты, разрыва корпуса и чистого узла. Зафиксировать время до первого ответа, память и ложные срабатывания. [MiniCPM-V 4.7 1B](https://huggingface.co/openbmb/MiniCPM-V-4.7-1B-gguf) имеет официальный GGUF и [Android-приложение](https://github.com/OpenBMB/MiniCPM-V-Apps), поэтому подходит для первого прогона. [VisionPsy-Nano 460M](https://arxiv.org/abs/2609.31746) — кандидат для сравнения скорости на том же Android и тех же изображениях.
