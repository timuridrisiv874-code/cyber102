# Детекторы Cyber102

Цель онлайн-модели — локализовать видимые дефекты на сервере RTX 3090 Ti. Для этого обучается YOLO11m при 768 px. Мобильный пилот YOLO11n обучен отдельно при 416 px. Формат ONNX использует тензор `[1, 3, размер, размер]` и выдаёт прямоугольники до NMS. Порог и постобработка должны пройти проверку на устройстве.

| Источник | Покрытие и этап |
| --- | --- |
| Фото Cyber102 | 29 кадров для обучения, 6 для валидации. Четыре класса — коррозия, следы жидкости, трещина, повреждение клеммы |
| MVTec AD Cable | Загружены PNG и маски. Восемь кабельных классов добавлены в эксперимент онлайн-детектора. Маски преобразованы в прямоугольники. Этот набор опубликован по CC BY-NC-SA 4.0 |
| Коррозия в промышленных комплексах Остравы | Загружены 105 фото с масками. Сохранено авторское разделение train, validation, test. Архив сверён по авторской контрольной сумме |
| PWDID | Архив получен, сверена контрольная сумма. Требуется проверить исходные фото и разметить прямоугольники для фотографий с метками на уровне изображения |
| VIP/PDI | У VIP по ссылке опубликована форма соглашения для получения данных |
| Roboflow Universe | Для выгрузки размеченных архивов через API нужен ключ Roboflow |
| Mendeley Oil Leak | Метка относится ко всему изображению. Для обучения локализации нужны прямоугольники или маски |
| Рентген сварных швов | Требует разметки и отдельной проверки на рентгеновских снимках |
| Hydraulic Components | Метки деталей гидросистемы можно использовать для привязки дефекта к узлу |

Оба пилота прошли экспорт и запуск ONNX на сервере. YOLO11s при пороге 0,25 нашёл коррозию в двух сценах `5.mp4` и дал одну лишнюю отметку коррозии на `2.mp4`. YOLO11n при этом пороге пропустил дефекты на десяти проверочных JPEG. Эти пилоты оставлены для сравнения. Офлайн-прогоны на Redmi отложены по просьбе пользователя.

В первом запуске YOLO11m 153 кадра для обучения, 37 для валидации и 8 контрольных фото. Обучение запущено на 80 эпох с ранней остановкой. Следующий проход продолжает с лучшего checkpoint и добавляет маски коррозии из Остравы.

Карта классов в `ml/defect_detector/classes.json` отражает целевое покрытие. Конкретный набор классов для обучения берётся из проверенной разметки. Пустые значения в отчёте покрытия означают, что на класс пока нет примеров. Результаты на независимых сценах должны храниться отдельно от метрик обучающей выборки.

## Сравнение моделей описания

Qwen3.5-2B и LFM3-VL-2B проверены на семи JPEG из приложения. Оба использовали модель Q4_K_M и проектор Q8. В прогоне с CUDA-энкодером и CPU-декодером медиана LFM составила 1,08 с, Qwen 1,99 с. LFM в этом прогоне ответил `clear` на трёх чистых кадрах, Qwen дал ложные признаки на двух. На сложных кадрах LFM иногда перечислял лишние дефекты. В отдельном CPU-прогоне с более короткой инструкцией обе модели ошибочно указали трещину на всех трёх контрольных кадрах. Медиана на CPU составила 3,36 с для LFM и 5,26 с для Qwen. Задержка измерена на сервере, качество чувствительно к формулировке инструкции.

MiniCPM-V 4.7 1B с обученной головой и исходным проектором заметил разрыв на двух JPEG из `2.mp4` и разделил трещину и ржавчину на контрольных JPEG из `5.mp4` при серверном тесте. Исходный генеративный MiniCPM обработал один кадр на Redmi за 109,3 с. Отдельный замер головы на Redmi прерван при отключении USB для зарядки Mac. На сервере подготовлен более компактный ускоренный проектор Q8. Его качество на мелком разрыве зависит от разрешения кадра.

## Цикл оценки онлайн-детектора

RGB-прогон YOLO11m v3 с 75 дополнительными кадрами коррозии достиг mAP50 0,265 на смешанной валидации. На десяти отложенных кадрах Cyber102 при пороге 0,25 и IoU 0,50 он пропустил четыре трещины, три повреждения клеммы и две рамки коррозии. На двух из трёх чистых кадров есть ложные отметки. У YOLO11s при таких же настройках совпала одна рамка коррозии, при этом на дефектных сценах остались 36 лишних или плохо локализованных рамок. Результаты получены на малой выборке с повторяющимися сценами. Несколько кадров одной сцены не дают статистики по независимым агрегатам.

YOLO11m v4 обучается на 1101 кадре. Добавлены 650 кадров трещин Steelcrack, вручную размеченные исходные панели 17 фотографий PWDID и 210 композиций для редких признаков из доноров только обучающей выборки. Для валидации выделено 155 кадров, для проверки из исходных датасетов — 104. Видео Cyber102 и фотографии контрольных узлов держатся вне обучения. Дополнительно подготовлены пять кадров из `3.mp4` и `4.mp4` для проверки переноса. Оценка с полным кадром и перекрывающимися кропами записывает точные попадания при IoU 0,30 и 0,50, ложные тревоги, пропуски и длительность обработки.

Рентгеновский YOLO11m поставлен после RGB-прогона. Из авторского набора SteelTube подготовлено 807 обучающих, 269 валидационных и 278 тестовых снимков. Варианты одной исходной фотографии и копии с совпадающим SHA-256 отнесены к одной выборке. Для подреза сварного шва в архиве удалось выделить только одну исходную группу, поэтому независимая оценка этого класса ещё требует данных. На тестовой части также отсутствует положительная разметка шлаковых включений.

[Steelcrack](https://github.com/hzlbbfrog/Civil-dataset) · [SteelTube](https://github.com/huangyebiaoke/steel-pipe-weld-defect-detection/releases/tag/1.0)

Промежуточный checkpoint RGB v4 проверен на тех же десяти кадрах Cyber102. При пороге 0,25 и IoU 0,50 совпадений с ручной разметкой пока нет. Модель поставила три ложные рамки на дефектных кадрах. Все три чистых кадра остались без отметок. Для сравнения поколений используется итоговый checkpoint после обучения.

В архиве Power Equipment Image Dataset размечено 23 повреждения клеммных соединений ЛЭП. Визуальная проверка показала, что снимки почти полностью состоят из видов одной группы высоковольтных соединений. Эти кадры пока исключены из обучения и оценки клеммной коробки двигателя.

Дым и пламя поставлены в отдельный прогон после рентгеновского. `ml/defect_detector/prepare_dfire.py` сформировал 1000 обучающих, 160 валидационных и 160 тестовых кадров D-Fire из веб-поднабора с равной долей чистых кадров, дыма, пламени и обоих признаков. Скрипт ограничивает рамки границами изображения и исключает побайтовые копии. Тестовые кадры берутся из авторского тестового раздела. Валидация выделяется из обучающего раздела. Класс пара требует собственного набора и контрольных сцен для проверки путаницы с дымом.

[Power Equipment Image Dataset](https://huggingface.co/datasets/sxiong/Power-equipment-image-dataset) · [D-Fire](https://github.com/gaia-solutions-on-demand/DFireDataset) · [Зеркало архивов D-Fire](https://huggingface.co/datasets/hanvithSai/gavin-dfire-raw)

### Сравнение на кадрах обхода

Проверочный кадр `original-terminal.jpg` исключён из следующего сравнения. Он показывает тот же клеммный блок, что и обучающий снимок `case-09.jpg`, с другого ракурса. На обновлённом наборе из 16 кадров, включая 6 контрольных, при пороге 0,25 и IoU 0,50 у v3 ноль из 13 совпадений и 4 лишние рамки. У промежуточного v4 ноль из 13 совпадений и 2 лишние рамки. Ложные тревоги на исправных узлах отмечены на 3 из 6 кадров у v3 и на 1 из 6 у v4.

Grounding DINO Base с текстовыми описаниями дефектов на первых десяти кадрах поставил две точные рамки коррозии и 26 лишних рамок, включая тревоги на всех трёх чистых кадрах. На пяти дополнительных кадрах из `3.mp4` и `4.mp4` при том же пороге он дал 0 совпадений и 6 лишних рамок. Медиана обработки на CPU во время обучения YOLO составила около 12,3 с на первых десяти кадрах. Этот прогон служит сравнением, развёрнутый сервис работает на InternVL3. [Grounding DINO Base](https://huggingface.co/IDEA-Research/grounding-dino-base)

В следующем прогоне v5 для кадров обхода используется 272 обучающих изображения. В них 166 рамок трещин, 445 рамок коррозии, 9 рамок повреждённых клемм и 2 рамки следов жидкости. Исключены синтетические вставки и лабораторные снимки кабелей, оставлено 160 обучающих фото Steelcrack. Для клемм добавлены пять вручную размеченных фото и один валидационный кадр. Проверен перенос весов четырёх общих классов из 18-классовой модели по именам на трёх масштабах головы YOLO. Эта модель проверяет четыре признака обхода. Целевой охват остальных классов оценивается в отдельных прогонах. ### Контроль переноса между типами оборудования

В более поздней проверке промежуточного v4 с 13 размеченными объектами девять пропусков не имели перекрытия при IoU 0,50. Для трёх объектов была рамка другого класса. В двух кадрах трещина корпуса из `5.mp4` получила класс кабельного дефекта. Ещё одна рамка коррозии имела правильный класс при уверенности 0,012. Все четыре перекрывающиеся рамки были ниже порога 0,25. Независимая фотография ржавого водопровода со струйкой и каплей добавлена к оценке как две области, коррозия и следы жидкости. Промежуточный v4 пропустил обе. [Протечка ржавой трубы, Shamrock Lee, CC BY 4.0](https://commons.wikimedia.org/wiki/File:Leak_in_rusted_pipe_side_view.jpg)

WTBs2025 содержит 520 изображений в категории масла, сгруппированных в 29 имён исходных фотографий и 17 групп по идентификатору лопасти в имени файла. В разработку выделены 102 кадра с масляными следами и 183 контрольных кадра пятен на лопастях. В валидации 4 положительных и 35 контрольных кадров, в тесте — 7 и 45. Для проверки оставлена только одна версия каждой фотографии. Эта выборка измеряет качество на лопастях ветротурбин. Для оценки переноса на насосные агрегаты нужны размеченные масляные следы именно на насосах. [WTBs2025, Ruihua Zhang, CC BY 4.0](https://figshare.com/articles/dataset/WTBs2025/28876391)

В S2DS маски высолов и отколов поверхностного материала преобразованы в рамки связных областей. Получено 562 обучающих, 87 валидационных и 93 тестовых кадра после исключения одной побайтовой копии. В обучении 404 рамки высолов и 361 рамка отколов, в тесте — 53 и 38 соответственно. Отколы служат примером внешнего повреждения кладки. Большинство исходных сцен относятся к бетону. Прогон предназначен для исследовательской проверки. [S2DS, Christian Benz и Volker Rodehorst](https://github.com/ben-z-original/s2ds)

Четыре видеосцены пара из обучающих примеров Project RISE отложены для контроля ложных тревог детектора дыма и пламени. Это один промышленный объект с четырьмя ракурсами. Кадры и ручная разметка хранятся на сервере. Датасеты изоляции VIP и IPD предоставляются по соглашению с авторами. [Project RISE, видео с паром](https://smoke.createlab.org/learn.html) · [VIP](https://zenodo.org/records/17398349) · [IPD](https://aiia.csd.auth.gr/ipd-dataset/)

### Проверка текущего сервиса и разрешения кадров

Живой API и рабочий процесс на 3090 Ti подтвердили модель Qwen3-VL-4B-Instruct с ревизией `ebb281ec70b05090aa6165b016eac8ec08e71b17`. Имя бэкенда осталось `internvl3`. Упоминание InternVL3 как действующих весов в предыдущих записях было неточным. [Qwen3-VL](https://github.com/QwenLM/Qwen3-VL)

Qwen в стандартном режиме обработал 16 кадров без ошибок формата. Он правильно отметил общее повреждение на 7 из 8 кадров с трещиной или клеммой, коррозию на 2 из 2 и следы жидкости на 0 из 1. Сработал на 3 из 6 чистых кадров. По координатам совпали 2 из 13 рамок при IoU 0,50. Промпт Qwen размечает узел целиком и сводит трещину и клемму к общему классу. Медиана обработки составила 7,36 с на GPU, параллельно шло обучение YOLO.

Зафиксированный промежуточный checkpoint YOLO11m v4 проверен на одних и тех же 16 кадрах с исходным разрешением видео 1280×720 и уменьшенными JPEG. При пороге 0,25 и IoU 0,50 совпадений нет ни в одном режиме. Число лишних рамок на уменьшенных JPEG при входе 768 px составило 2, на оригиналах при 768 px — 1, при 1024 px — 0. Медианы обработки на CPU составили 309, 298 и 465 мс соответственно. На этом наборе повышение разрешения не устранило пропуски.

В очереди 3090 Ti v5 поставлен сразу после v4, затем идут рентген, дым и пламя, масло и высолы. Веса v5 будут сопоставлены с Qwen и итоговым v4 на тех же сценах. Замена рабочего маршрута пока не выполнялась.
