# Локальный процесс компьютерного зрения

На стенде выбран **Qwen3-VL-4B-Instruct**: ревизия `ebb281ec70b05090aa6165b016eac8ec08e71b17`, каталог `models/qwen3-vl-4b-instruct`. Используются native `Qwen3VLForConditionalGeneration`, BF16/SDPA и тот же Transformers 4.57.1. Снимок содержит 13 проверенных файлов общим размером 8,89 GB. InternVL3.5-2B сохранена как проверенная альтернатива. [Закреплённый снимок Qwen](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct/tree/ebb281ec70b05090aa6165b016eac8ec08e71b17)

Оба задания Windows читают `C:\cyber102\var\vlm-model.txt`. Значение `qwen3_vl_4b` выбирает Qwen, `internvl3_5` — InternVL3.5. После изменения перезапускаются оба задания, `Cyber102InternVL` и `Cyber102Web`; имя backend `internvl3` сохраняется для совместимости HTTP-контракта. При отсутствии файла остаётся прежнее значение InternVL3.5. Неизвестное имя завершает запуск ошибкой. Для ручного запуска Qwen укажите `--model qwen3_vl_4b` процессу модели и `CYBER102_VLM_MODEL=qwen3_vl_4b` процессу веб-API.

Загрузка Qwen выполняется вне изолированного runtime командой `python -m vision_runtime.qwen_download --directory models/qwen3-vl-4b-instruct`. Затем проверенный каталог передают на сервер. Исходящие блокировки Python и офлайн-проверки одинаковы для обеих моделей; для переключения не нужно менять Firewall.

## Сохранённая конфигурация InternVL3.5

GPU-процесс Cyber102 обслуживает запросы веб-API на `127.0.0.1:11436`. Для Windows 11 с RTX 3090 Ti выбран `OpenGVLab/InternVL3_5-2B-HF`, ревизия `3f301ffcf3dcbb47893afae6650ea3e78d96fb6d`. Модель использует нативные `InternVLForConditionalGeneration` и `Qwen3ForCausalLM`, BF16 и SDPA. Снимок совместим с закреплённым Transformers 4.57.1 без загрузки стороннего Python-кода. При недоступной CUDA запуск завершается ошибкой. [Закреплённый снимок](https://huggingface.co/OpenGVLab/InternVL3_5-2B-HF/tree/3f301ffcf3dcbb47893afae6650ea3e78d96fb6d) · [Документация Transformers 4.57.1](https://huggingface.co/docs/transformers/v4.57.1/en/model_doc/internvl)

Файл весов InternVL3.5 имеет размер 4 696 790 328 байт (~4,37 GiB); tokenizer и конфигурация увеличивают комплект примерно до 4,71 GB. Результаты сравнения с Qwen3-VL-4B приведены выше. Новый номер модели и общие бенчмарки не доказывают качество на оборудовании заказчика: нужны одинаковые размеченные фото и клипы. Данные старых latency-отчётов InternVL3 не являются измерениями InternVL3.5.

## Подготовка Windows

В `C:\cyber102` требуется отдельное Python 3.11 окружение `.venv-internvl`. Используются `torch==2.8.0+cu128`, `torchvision==0.23.0+cu128` и `transformers==4.57.1`. CUDA-колёса ставятся первыми из индекса PyTorch или подготовленного wheelhouse. Остальные зависимости перечислены в [requirements.txt](requirements.txt). [Сборки PyTorch для CUDA](https://pytorch.org/get-started/previous-versions/)

Для установки из подготовленного wheelhouse используйте PowerShell в каталоге проекта. Wheelhouse должен содержать указанные CUDA-колёса и зависимости Windows x64 для Python 3.11.

```powershell
Set-Location C:\cyber102
.\runtime\python.exe -m venv .venv-internvl
.\.venv-internvl\Scripts\python.exe -m pip install --no-index --find-links wheelhouse `
  'torch==2.8.0+cu128' 'torchvision==0.23.0+cu128'
.\.venv-internvl\Scripts\python.exe -m pip install --no-index --find-links wheelhouse `
  -r vision_runtime\requirements.txt
.\.venv-internvl\Scripts\python.exe -m pip check
```

На машине с доступом к Hub запустите загрузку зафиксированной ревизии. Веса, настройки и манифест передайте в новый `C:\cyber102\models\internvl3_5-2b-hf`. Старый каталог `internvl3-2b-hf` сохраняется для отката вместе с предыдущей версией приложения. Загрузчик сверяет ревизию, хеши файлов с метаданными Hub и записывает SHA-256 в `cyber102-manifest.json`. Он скачивает только данные и safetensors, исключает Python-файлы и вложенные примеры.

```powershell
python -m vision_runtime.download --directory models/internvl3_5-2b-hf
# Штатный отдельный curl.exe получает файлы, Python только проверяет хеши:
python -m vision_runtime.download --directory models/internvl3_5-2b-hf --curl
```

При инференсе процесс читает локальные safetensors и настройки через `local_files_only=True` и `trust_remote_code=False`. Включены офлайн-переменные Hugging Face и Python audit hook, отклоняющий внешние DNS-запросы и соединения процесса. Этот hook действует на Python-операции. На действующем стенде дополнительно включены два правила Windows Firewall: исходящие соединения запрещены для `.venv-internvl\Scripts\python.exe` и частного `runtime\python.exe`. Скрипт [lock-inference-network.ps1](../deploy/lock-inference-network.ps1) ограничен этими процессами. Проверка внешнего HTTPS завершилась `WinError 10013`, а анализ через loopback продолжил работать. Для обновления весов используют отдельный загрузчик вне изолированного runtime и передают проверенные файлы. Это изоляция процессов модели и приложения; HTTPS от телефона к удалённому серверу остаётся сетевой передачей. [Офлайн-режим Hub](https://huggingface.co/docs/huggingface_hub/en/package_reference/environment_variables#hfhuboffline)

## Запуск и проверка

После установки окружения и весов в PowerShell администратора запустите `C:\cyber102\deploy\install-internvl.ps1`. Он регистрирует `Cyber102InternVL` для старта Windows под `fatik` и перезапуска при сбое. Сначала убедитесь, что процесс модели готов.

```powershell
Get-ScheduledTask -TaskName Cyber102InternVL | Select-Object TaskName,State
Invoke-RestMethod http://127.0.0.1:11436/health
Get-Content C:\cyber102\var\internvl-worker.log -Tail 20
nvidia-smi
```

`/health` сообщает идентификатор и ревизию, CUDA-устройство, занятость модели и поддержку `sampled_multi_image`. Стабильное имя backend остаётся `internvl3` в `C:\cyber102\var\vision-backend.txt`; оно обозначает общий локальный API. Убедитесь, что `/health`, `/analyze` и `/api/capabilities` сообщают выбранную модель и закреплённую ревизию. Ошибка выбранной модели возвращается клиенту, подмена демо-ответом не применяется. Перед переключением рабочего процесса проверяйте новый worker на свободном loopback-порту через `--port 11437`; при замере памяти и скорости одновременно должна работать только одна модель.

## Интерфейс процесса

Внутренний `POST /analyze` принимает JSON с одним Base64-изображением JPEG или PNG до 3 МиБ. Запрос передаёт только кадр, а инструкции задаёт приложение. Один запрос выполняется на GPU в каждый момент. Сервис валидирует наблюдение, журналирует время и статус без сохранения изображений и возвращает `model`, `observation` и `durationSeconds`. Публичный маршрут веб-приложения сохраняет прежний формат multipart. [Архитектура камеры](../docs/architecture/vision.md)

`POST /analyze-video` выполняет **один совместный multi-image вызов** для 1–8 выбранных кадров, а не цикл независимых описаний фото. Максимальная длительность исходного клипа 120 секунд. Вход:

```json
{"frames":[{"image":"<base64 JPEG/PNG>","timestampSeconds":0},{"image":"<base64 JPEG/PNG>","timestampSeconds":2.5}],"durationSeconds":5}
```

`durationSeconds` во входе необязателен. Позиции кадров конечны, неотрицательны, строго возрастают и укладываются в длительность, если она задана. Каждый кадр ограничен 3 MiB / 8 мегапикселями. Передавать URL, промпты, параметры генерации или звук нельзя. Сервер нормализует кадры перед внутренним вызовом; публичные суммарные ограничения могут быть строже.

Ответ содержит `model`, `revision`, `observations`, `summary`, `durationSeconds`, `clipDurationSeconds`, `metrics`. В **ответе** `durationSeconds` означает измеренное время обработки, `clipDurationSeconds` — длительность исходного ролика либо `null`. Каждое наблюдение содержит `frameIndex`, `timestampSeconds`, `component`, `condition`, `box`, `observation`; индексы идут от 0 по порядку. Рамка `[left,top,right,bottom]` относится к своему кадру и нормализована в 0–1000. Worker требует результат для каждого входного кадра; неполный/повторный индекс или неподдержанный класс даёт ошибку 502. Время берётся из проверенного запроса, а не из текста модели.

`none/uncertain` сохраняет отказ от вывода. `other` обозначает иной явно промышленный узел, без автоматической привязки к паспорту насоса. Модель не получает основания выдумывать серийный номер, остаточный ресурс, показания или срок ремонта. Разреженные кадры и отсутствие звука не подтверждают характер вибрации, непрерывность течи и события между кадрами. `summary` — предварительное описание видимого, не подтверждённый диагноз.

Фото и клипы используют один GPU-lock; занятость даёт 503 `vision_busy`. Для видео лимит генерации 1800 токенов, `max_time=110`. InternVL использует максимум два пространственных патча на кадр плюс возможную миниатюру. Qwen ограничивает каждый кадр 786 432 пикселями с сохранением пропорций и округлением к своей сетке. Текущий путь передаёт кадры как несколько изображений с текстовыми таймкодами; отдельный нативный видеопроцессор Qwen пока не используется. Общий лимит внутреннего HTTP-вызова со стороны API — 150 секунд. Системная инструкция требует русских описаний, а короткие фразы кадров ограничивают объём ответа; это не заменяет проверку фактической точности.

## Фактическая проверка 13 ноября 2026

Закреплённая InternVL3.5-2B загружена в нативном Transformers 4.57.1 на RTX 3090 Ti, BF16/SDPA, с `trust_remote_code=False` и офлайн-ограничениями. Все 14 файлов снимка (4 712 721 400 байт) сверены по SHA-256 на Windows. Проверка выполнена на отдельном loopback-порту 11437 при сохранённом рабочем процессе предыдущей модели.

| Проверка | Результат | Время внутреннего HTTP-вызова |
| --- | --- | ---: |
| Синтетический насос, подробный режим | Корректный контракт ответа | 5,38 с |
| Синтетический чистый насос | Корректный контракт ответа | 4,69 с |
| Белый кадр | `none/uncertain` | 3,55 с |
| Неразмеченная открытая фотография насоса | Корректный контракт ответа | 4,86 с |
| Синтетический насос, быстрый режим | Классы и русский шаблон | 3,42 с |
| Два одинаковых синтетических кадра с временами 0 и 2 с | Ровно 2 наблюдения | 15,20 с |
| Восемь одинаковых синтетических кадров с временами 0–14 с | Ровно 8 наблюдений; 624 выходных токена | 50,02 с |

Это отдельные измерения функциональной совместимости, а не оценка полевой точности, стабильного p95 или распознавания движения в настоящем видео. В исходном восьмикадровом запросе модель спутала последнее время 14 с с количеством кадров и выдала 15 наблюдений; строгий контракт отклонил ответ. В окончательной инструкции явно передаются число изображений и допустимые индексы. Неверные или лишние наблюдения не обрезаются для искусственного получения успешного ответа.

Сохраняются качественные ограничения: модель по-разному описывала один синтетический кадр отдельно и в группе, ошибалась в названии узла, иногда смешивала русский с английским или китайским. Русская инструкция уменьшила проблему языка, но не устранила её полностью. Результаты требуют проверки инженером; перенос на другие виды оборудования и преимущество над предыдущей моделью этими тестами не доказаны. Отдельные фото и совместный контекст могут выбирать разные видимые узлы, поэтому сравнение классов без ручной проверки рамок недостаточно.

Ограничение `max_time` (85 секунд для фото и 110 для видео) в Transformers проверяется между шагами генерации и не является жёстким пределом всего GPU-вызова. Отмена запроса в браузере не прерывает текущий GPU-вызов. Второй вызов отклоняется, пока первый не завершится. Версии установленного Windows-окружения записаны в [requirements-lock-windows.txt](requirements-lock-windows.txt).
