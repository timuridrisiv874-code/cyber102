# Cyber102 для Android

## Версия 0.6-test

Добавлены системный выбор фото/видео без разрешения на всё хранилище, покадровая проверка загруженного ролика, ручной ввод показаний, навигатор следующей проверки и рекомендации со страницами PDF. Общие `app.js`, `media.js`, `inspection.js` и `styles.css` синхронизированы с вебкой. APK: [готовая сборка](../output/android/Brovi_Resnitsy_0.6-test.apk). Перед показом проверить системный выбор JPEG/MP4 и возврат из PDF на реальном телефоне.

Тестовая Android-оболочка общего веб-интерфейса. Минимальная версия Android 8.0 (API 26), compile/target API 36. Код оболочки написан на Java с системным WebView, внешних runtime-библиотек и Google Play Services нет.

## Версия 0.5-test

Добавлены подробный и быстрый анализ, измерение задержки, ограниченные повторы при занятой GPU, подтверждение признаков инженером и сохранение кадра с диагностикой в историю. Быстрый режим сохраняет детализацию изображения; модель возвращает классы и рамку, русское пояснение формируется по классу. Источник телеметрии выбирается явно: без данных либо демонстрационный сценарий.

## Установка и подключение

1. Установите Brovi_Resnitsy_0.5-test.apk. Android может запросить разрешение установки для приложения, из которого открыт APK.
2. На первом запуске выберите сервер и введите HTTPS-адрес, логин и пароль команды.
3. Кнопка «Сервер» позволяет изменить подключение. Адрес сохраняется, логин и пароль нужно вводить снова после завершения процесса приложения.
4. Нажмите «Включить камеру» и разрешите доступ. При отказе приложение объясняет, как открыть настройки.

Настройка адреса принимает URL общего экрана, например https://your-host.example/. Участник 1 задаёт data-analysis-endpoint="/analyze" в main своего index.html. Веб-экран и API следует отдавать с одного HTTPS-адреса с доверенным сертификатом. При редиректе на другой хост укажите конечный адрес. HTTP и самоподписанные сертификаты не поддерживаются.

Встроенное демо использует исходные web/ без изменений. Любой снимок камеры в демо получает заранее заданный ответ, о чём сообщает постоянная строка «Демо · ответы заданы заранее». Реальное распознавание включается на странице сервера после настройки API. Срок службы и сроки ТО берутся из JSON.

## Сборка

Откройте каталог android в Android Studio. Установите JDK 17+, SDK Platform 36. Выполните ./gradlew assembleDebug lintDebug. APK появится в app/build/outputs/apk/debug/app-debug.apk. Gradle 8.13 и AGP 8.13.0 зафиксированы. Debug APK подписывается локальным тестовым ключом. При смене ключа понадобится удалить ранее установленную тестовую версию.

Страница камеры берётся из app/src/main/assets/inspection; она встроена в APK и использует API выбранного HTTPS-сервера. Изменения этой страницы требуют пересборки APK. Паспорт, материалы и история загружаются с сервера. Копии inspection.js для вебки и Android должны совпадать.

## Проверка перед защитой

На Tecno Camon 20 Pro 5G с Android 14:

- Установить APK с нуля и открыть каждый из трёх примеров.
- Разрешить камеру и проверить, что выбрана задняя.
- Отказать в разрешении, затем выдать его через настройки и повторить запуск камеры.
- Проверить поворот, крупный системный шрифт, жестовую навигацию.
- Свернуть приложение, вернуться и снова включить камеру. Снятый кадр должен остаться доступен, пока процесс приложения жив.
- Проверить неверный адрес, отключение сети, остановку сервера и повторную загрузку.
- На сервере проверить defect, clear, no_marker, unusable, ошибочный JSON и тайм-аут.
- Повторить показ в сети площадки.

Минимальная версия ОС в сборке не доказывает совместимость с каждой моделью. Актуальный Android System WebView необходим для возможностей веб-экрана. При завершении процесса системой снятый кадр теряется, адрес сохраняется.
