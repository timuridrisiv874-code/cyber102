# Набор материалов заказчика

Пакет включает 58 оригиналов. 53 изображения разложены по категориям оборудования, 2 XLSX содержат почасовые примеры вибрации и температуры, 3 DOCX описывают измерительные каналы, пороги и видимые признаки дефектов. Изображения зарегистрированы для осмотра. Физический источник каждого кадра и право на распространение требуют проверки. [Контракт и ограничения](../../docs/architecture/customer-data.md)

Дополнительно получены 22 PDF организаторов: паспорта насосов и узлов, руководства, сертификаты, чертежи и смазочные материалы. [Реестр и проверенные сведения](../../docs/architecture/equipment-passports.md). Это отдельный набор; сведения о винтовых насосах не подменяют демо-профиль P-102 и не создают неподтверждённую связь с Excel.

Эмулятор `GET /api/telemetry/snapshot?index=N` выдаёт исходную строку и сохраняет неизвестные входы. [Контракт](../../docs/architecture/telemetry-integration.md).

## Повторный импорт

Подготовьте отдельное окружение Python и установите зависимости импорта. Pillow применяется для создания JPEG-превью. openpyxl читает XLSX. Веб-сервер использует готовые файлы.

```bash
python -m pip install -r data_tools/requirements-customer.txt
```

Из корня репозитория укажите каталог, где лежат папки `Вибрация`, `Температура`, `Насосные агрегаты`, `Запорная арматура`, `Турбопровод` и `ЭД`, а также документ «Типы дефектов промышленного оборудования.docx». `<папка-материалов>` в командах замените фактическим путём.

```bash
python -m data_tools.import_customer_materials --source-root "<папка-материалов>" --output-root data/customer
python -m data_tools.import_customer_sensors --source-root "<папка-материалов>" --output-dir data/customer --as-of 2026-11-13
```

Импорт изображений сохраняет исходники изображений и справочника в `raw/` и создаёт превью. Сенсорный импорт создаёт два JSON. Для комплектования стенда поместите исходные четыре сенсорных файла в `raw/Вибрация` и `raw/Температура`, сохраняя имена и проверяя хеши по манифесту. На сервер передайте подготовленный `data/customer`. Подкаталоги `raw/` и `previews/` игнорируются Git и передаются отдельно от исходного кода.

Проверьте каталог по `GET /api/customer/materials`, сенсорные данные по `GET /api/customer/sensors` и одно превью по `GET /api/customer/images/<sha>`. В `materials.json` поле `summary.files` считает 54 файла, обработанные импортом изображений и справочника. Ещё четыре сенсорных файла отражены в сенсорном манифесте.

[Фактический прогон модели](vision-smoke-report.json) содержит 53 предварительных результата с хешами кадров и промпта. Автоматические ответы остаются отдельными от экспертной разметки.

[Проверка выпуска](validation-report.json) фиксирует автотесты и браузерные прогоны; имена файлов хранятся в Unicode NFC для переноса на Windows.

### База знаний оборудования и демонстрационные показания

`equipment-knowledge.json` содержит паспортные выдержки и данные конкретных моделей. В `inspection-knowledge.json` хранятся русскоязычные справки с издателем, прямой ссылкой и областью применения. Справки доступны в вебке и API без обращения к внешним сайтам. Запись из справки не получает серийный номер агрегата. Для AMS PCP и центробежных насосов используются разные области поиска. Список отдельных разделов справочника возвращает `GET /api/equipment/models` в поле `sections`. Например, `GET /api/equipment/knowledge?section=motor` возвращает справки по двигателям без привязки к серийному номеру.

В фото и видео передаётся ограниченный контекст выбранного серийного номера с паспортными ссылками и справкой по типу узла. Синтетическая телеметрия в этот контекст не попадает.

На странице «Оборудование» можно открыть оригинальные фотографии серии AMS PCP, посмотреть четыре паспортные группы и найти выдержки по серийному номеру и узлу. Две модели Катайского насосного завода представлены каталожными карточками. RAG использует локальные выдержки с привязкой к странице паспорта и передаёт ограниченный контекст модели при локальном анализе фото и видео.

Для локального показа запустите сервер с отдельной базой:

```sh
python -m server.app --port 8000 --database var/cyber102-demo.sqlite3 --telemetry-emulator
```

Затем откройте `/index.html?serial=21031004-2` и разверните «Показания насоса · эмулятор». Сервер обновляет данные каждые 5 секунд, хранит 60 минут в SQLite и возвращает последние 12 точек. Для вибрации и температуры используется форма ряда из архива заказчика. Точки эмуляции получают свои временные метки и отдельный признак `simulated`. Архивные точки сохраняют исходные метки времени и отсутствие серийного номера.
