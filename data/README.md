# Локальный набор фотографий Cyber102

Фотографии хранятся локально в `data/raw/unlabelled/`, а происхождение каждого файла записано в `data/raw/manifest.json`. В манифесте есть страница оригинала, прямая ссылка, автор, лицензия, атрибуция, размер кадра, контрольная сумма SHA‑256 и время загрузки. Исходный список файлов и поисковых запросов лежит в `data_tools/commons_sources.json`.

Коллектор ищет точную модель насоса Д 160-1126, затем собирает референсы центробежных насосов, муфт, электродвигателей, подшипниковых узлов, уплотнений и манометров. `model_match: model_number_mentioned` означает совпадение номера в названии или описании, которое нужно подтвердить по паспорту или шильдику. `reference_only` означает фотографию похожего оборудования или отдельного узла. [Описание API Wikimedia Commons](https://www.mediawiki.org/wiki/API:Imageinfo)

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r data_tools/requirements.txt
.venv/bin/python -m data_tools.collect_commons --count 25
```

`--count` задаёт целевой размер локального набора до 40 файлов. Повторный запуск с той же папкой пропускает уже зарегистрированные URL и проверяет SHA‑256 новых файлов. Загрузчик принимает JPEG и PNG до 12 МиБ и проверяет содержимое с помощью Pillow. Используются публичные материалы с CC BY, CC BY-SA, CC0 или пометкой Public domain. При HTTP 429 или 503 загрузка останавливается и сохраняет уже принятые файлы. Повторите запуск после интервала из `Retry-After`, если сервер его указал. [Рекомендации MediaWiki по использованию API](https://www.mediawiki.org/wiki/API:Etiquette)

Все файлы поступают в `unlabelled`. Поле `subject_hint` служит для сортировки и требует ручной проверки. Перед разметкой проверьте вид узла, происхождение, права использования и необходимость атрибуции. Подтверждайте состояние по наблюдениям и данным диагностики. Открытые фотографии дают примеры внешнего вида и ракурсов. Для калибровки признаков модели нужны подтверждённые снимки нужного агрегата, его паспорт и связанные с осмотром показания датчиков.
