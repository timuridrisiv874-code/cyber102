# Браузерная проверка видеорежима

Проверки обновлённого интерфейса и Android assets:

- `node tests/browser/motor-resource-smoke.cjs` — реестр паспортов → расчёт наработки двигателя до анализа фото, затем выбор двигателя при осмотре насоса. Проверяется свой номер, счётчик, страница каждого выбранного паспорта и очистка предыдущего ввода при смене узла.
- `node tests/browser/video-history-smoke.cjs` — видеоосмотр в мобильных браузерах (Pixel 7 и iPhone 13 в эмуляции). Проверяются выбор MP4, сохранение без повторного запроса к модели, соответствие JPEG опорному кадру, сводка и таймкоды после перезагрузки. Сервер, очередь и SQLite настоящие, ответы VLM фиксированы. Нужны FFmpeg, Playwright и Python с зависимостями проекта.
- `node tests/browser/design-smoke.cjs` — 320/390/1440 px, Chromium/WebKit, общий веб-интерфейс и Android bundle; загрузка ресурсов, анимации и reduced motion, отсутствие внешних запросов и горизонтального переполнения. `DESIGN_SMOKE_SCREENSHOTS` задаёт каталог PNG.
- `node tests/browser/clip-review-smoke.cjs` — настоящий MP4 и тестовый ответ сравнения: восемь разных JPEG в одном запросе, превью и CSP Android, таймкоды и переход по ним, отказ при несовпадении кадров, отмена, недоступная серверная функция. Нужен FFmpeg. Тест проверяет интеграцию интерфейса, а не качество модели.
- `node tests/browser/offline-smoke.cjs` — общий интерфейс на origin Android assets с имитированным нативным мостом. Проверяет изоляцию от серверного API; реальную скорость SmolVLM и расход памяти нужно проверять в APK на телефоне.

Версия 0.6:

- `node tests/browser/media-smoke.cjs` — настоящие PNG/MP4, ответы модели имитированы: декодирование, JPEG, таймкоды, последовательная обработка, лимиты, отмена и очистка файлов. Нужен FFmpeg для тестовых роликов.
- `node tests/browser/gold-smoke.cjs` — настоящий Python API и временная SQLite, тестовое свидетельство вместо модели: ручные показания, следующая проверка, сохранённые основания, паспортные цитаты, границы применимости и отсутствие переполнения мобильной формы. Путь к Python с зависимостями проекта можно задать в `CYBER102_TEST_PYTHON`.

Оба теста проверяют Chromium/WebKit и вебку/встроенные Android assets. Они не заменяют проверку камеры и системного выбора файлов на физическом телефоне.

Из корня репозитория выполните команду в окружении с Node.js 18+, Playwright, Chromium и WebKit.

```sh
node tests/browser/video-smoke.cjs
```

Для уже установленного рантайма можно задать абсолютный путь к модулю в `PLAYWRIGHT_MODULE`, каталог браузеров в `PLAYWRIGHT_BROWSERS_PATH` и путь к системному Chrome в `CHROME_PATH`. Для сохранения PNG укажите каталог в `VIDEO_SMOKE_SCREENSHOTS`.

Тест использует синтетическую камеру и имитирует ответы `/analyze` на локальном HTTP-сервере. В Chromium и мобильном профиле WebKit он проверяет отправку JPEG, последовательность запросов при задержке ответа, рамку на проверенном кадре, отмену при остановке и уходе со страницы, одиночный кадр и обработку ошибки. Для проверки камеры телефона и модели на GPU нужен отдельный прогон.

## Материалы заказчика

После подготовки каталога, превью и примеров измерений запустите из корня репозитория локальный экземпляр.

```sh
python3 -m server.app --port 8130
```

Во втором терминале из корня выполните браузерную проверку.

```sh
node tests/browser/materials-smoke.cjs
```

Проверка использует реальные маршруты каталога, измерений и диагностики. Ответы модели `/analyze` имитируются. Для другого локального адреса задайте `CYBER102_SMOKE_URL`, для сохранения PNG — каталог в `MATERIALS_SMOKE_SCREENSHOTS`.

## Паспорта и воспроизведение показаний

После импорта 22 PDF организаторов выполните `node tests/browser/workspace-smoke.cjs` при работающем локальном сервере на порту 8130. Проверяются каталог и оригинал PDF, поиск по документам, паспортный номер, воспроизведение 500 строк, пауза, выбор позиции, последняя строка, отмена запросов и восстановление после возврата на страницу. Данные читаются из настоящего API; ошибка источника и задержки запросов имитируются для проверки интерфейса. `WORKSPACE_SCREENSHOTS` задаёт каталог PNG.

Для защищённого HTTPS-стенда передайте его адрес в `CYBER102_SMOKE_URL`, а путь к игнорируемому JSON с `username` и `password` — в `CYBER102_ACCESS_FILE`. Учётные данные ограничены выбранным origin. Этот тест не проверяет разрешение физической камеры телефона.

## Проверка действующего GPU-стенда

`node tests/browser/live-video.cjs` отправляет синтетические кадры на настоящий `/analyze` выбранного HTTPS-стенда. Веса должны быть запущены заранее; тест проверяет InternVL3-2B-hf. Учётные данные читает из игнорируемого `var/deploy-access.json` (`url`, `username`, `password`) или файла в `CYBER102_ACCESS_FILE`, передаёт заголовок входа только выбранному origin. Используются те же `PLAYWRIGHT_MODULE`, `PLAYWRIGHT_BROWSERS_PATH`, `CHROME_PATH`, `VIDEO_SMOKE_SCREENSHOTS`. Результат сохраняется в `var/internvl-browser-report.json`; секреты в отчёт не входят. Камера синтетическая, модель и HTTPS настоящие. Скрипт требует сетевого доступа и не входит в обычный набор unit-тестов.

`node tests/browser/live-materials.cjs` проверяет раздел материалов на действующем HTTPS-стенде: каталог, измерения, реальный анализ фото на GPU и ручное правило кожуха. Использует те же переменные Playwright и `CYBER102_ACCESS_FILE`, что `live-video.cjs`. Сохраняет обезличенный протокол в `var/customer-browser-report.json`. Для обычной локальной проверки с имитацией только `/analyze` используйте `materials-smoke.cjs`.
