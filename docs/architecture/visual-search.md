# Поиск похожего оборудования по фото

Веб-осмотр автоматически отправляет загруженное фото или первый готовый кадр видео в `POST /api/equipment/similar`. При проверке кадра камеры поиск запускается вместе с основным анализом. Найденные образцы и справочные ссылки появляются в блоке «Похожее оборудование». Смена фото отменяет предыдущий запрос. Поиск сохраняет выбранный оператором серийный номер.

Это подбор визуальных кандидатов. Каталожный образец относится к серии, а фотографии заказчика не связаны с конкретными экземплярами. Совпадение не подтверждает точную модель, серийный номер, дефект или ресурс. При обычном анализе фото сервер сам повторяет визуальный поиск, разрешает найденные ID в локальные выдержки и передаёт их текст модели вместе с выбранным паспортом. Результат содержит только реально включённые в запрос источники и пометку `selection=visual_similarity` или `passport_and_visual`. В интерфейсе они отмечены «найдено по фото». Сходство возвращается как косинусная мера, без перевода в вероятность правильной идентификации. Выдаются до трёх кандидатов с мерой не ниже 0,45 и отставанием от первого не более 0,10. Это эвристика отсечения слабых вариантов, а не откалиброванный порог достоверности. Для однотонного кадра возвращается пустая выдача.

## Контекст анализа фото

Общий лимит остаётся 1300 символов и до трёх источников. Паспорт выбранного оператором экземпляра имеет приоритет; несовместимая насосная серия отбрасывается. Для похожей каталожной модели используются процедурные выдержки, без переноса численных характеристик аналога. Общие фотографии насосов без подтверждённого типа дают общие справки по уплотнениям, подшипникам и давлению. Текст берётся из локальных `inspection-knowledge.json` и `equipment-knowledge.json`; ссылки не скачиваются во время анализа.

При недоступности поиска анализ продолжает работать с выбранным паспортом либо без справок. Повтор асинхронного запроса сохраняет исходное задание даже при временной недоступности поиска. Кеш результата учитывает фактически переданный контекст и версию кода подбора. Это действует для профиля `standard`; `--without-vision-knowledge` отключает оба вида контекста, режим детектора справки не принимает. Сводка всего видео сохраняет существующий паспортный контекст; отдельный проверяемый кадр получает автоматические справки как фото.

[Контрольный анализ на рабочем сайте](../ml/visual-rag-integration-2026-11-14.json) подтверждает ответ Qwen3.8-27B с автоматически выбранными справками и их происхождением. Отдельные браузерные проверки Chromium и WebKit проверяют показ использованных источников после настоящего анализа фотографии.

## Устройство и нагрузка

Работает отдельный процесс `vision_runtime.visual_worker` на `127.0.0.1:11437`. Он использует только CPU, два вычислительных потока и один слот обработки. Основная Qwen и очередь GPU не меняются. Прокси веб-приложения не импортирует PyTorch. Если поиск выключен или занят, осмотр продолжает работать; в блоке поиска появляется возможность повторить запрос.

Модель — DINOv2 Small, `timm/vit_small_patch14_dinov2.lvd142m`, ревизия `4610ca143709d58a633b6397a74412c2c3842454`. Веса Safetensors проверяются по SHA-256 `04d27f3400d059fc0cfd7d17dd1909a75bf3ea8fb3eeb48b97cb99e57ee20081` и загружаются только с локального диска. Изображение с сохранением пропорций дополняется до квадрата 224 × 224; выход — нормированный вектор из 384 чисел. [Карточка модели](https://huggingface.co/timm/vit_small_patch14_dinov2.lvd142m) · [Извлечение признаков timm](https://huggingface.co/docs/timm/feature_extraction).

Индекс включает 10 локальных каталожных фото из `visual-catalog.json` и доступные JPEG-превью 53 изображений заказчика. Векторы сохраняются в `var/visual-search/index.npz`. Отпечаток учитывает модель, обработку, метаданные, ссылки и содержимое каждого фото. При изменении набора индекс пересобирается на старте. Новые загруженные фотографии не сохраняются; кеш последних 32 ответов содержит хеши и найденные образцы. Для добавления эталонов обновите каталог и перезапустите CPU-процесс.

[Локальный технический прогон](../ml/visual-search-smoke-2026-11-14.json) на macOS arm64: веса 88,2 МБ, индекс около 90 КБ, максимум памяти процесса 541 МиБ; десять запросов после загрузки — 22–26 мс каждый. Это не замер Windows-сервера и не гарантия времени HTTP-ответа. По существующим широким категориям 53 фото поиск без самого запрошенного фото нашёл ту же категорию первым в 34 случаях, в первой тройке — в 47. Эти категории не являются разметкой точной модели. Поиск конкретных моделей требует проверенных эталонов с разных ракурсов и отдельной оценки.

На рабочем Windows-сервере поиск включён отдельной задачей `Cyber102VisualSearch`. [Проверка через HTTPS](../ml/visual-search-server-2026-11-14.json): три запроса заняли 91–113 мс внутри поиска и 143–215 мс вместе с HTTP. Снимок памяти после загрузки: рабочий набор 388,6 МиБ, приватная память 900,5 МиБ; это не пиковый замер. На публичном сайте прошли проверки Chromium и WebKit с мобильными размерами экрана, включая справки, сохранение серийного номера, устаревшие ответы и повтор после ошибки. Основной GPU-процесс продолжает работать отдельно.

## Локальный запуск

Подготовка выполняется с доступом к сети. Для Windows/Linux сначала установите CPU-сборки `torch==2.8.0` и `torchvision==0.23.0` из `https://download.pytorch.org/whl/cpu`. На macOS подходят обычные колёса PyPI.

```sh
python3 -m venv .venv-visual
.venv-visual/bin/python -m pip install -r vision_runtime/visual-requirements.txt
.venv-visual/bin/python -m vision_runtime.visual_worker --prepare
.venv-visual/bin/python -m vision_runtime.visual_worker
```

Для подготовки без сети используется `--prepare --source-weights /path/to/model.safetensors`. Веса должны иметь указанный хеш. В другом терминале запустите веб-приложение обычным способом. Готовность CPU-процесса: `GET /health` на 11437; через веб-приложение: `GET /api/equipment/similar`.

## Windows-сервер

Передайте новые исходники, каталог, фото и `models/visual-search/model.safetensors` в `C:\cyber102`, сохраняя рабочие данные и прочие модели. При закрытом исходящем доступе заранее подготовьте совместимые Windows x64 Python 3.11 колёса из `visual-requirements.txt` в `wheelhouse-visual`. Установщик использует их без обращения к сети.

Из административного терминала выполните `powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\cyber102\deploy\install-visual-search.ps1`. Разрешение выполнения действует для этого процесса. Установщик создаёт отдельное окружение, устанавливает CPU-зависимости, регистрирует задачу `Cyber102VisualSearch`, ждёт готовности индекса и завершения текущих анализов, затем перезапускает только `Cyber102Web`. Лог — `var/visual-search.log`. Для поэтапного обновления доступен `-SkipWebRestart`. Установщик CPU-поиска не перезапускает GPU-процесс. При обновлении `server/knowledge.py` нужно также перезапустить `Cyber102InternVL` после завершения текущих анализов, чтобы обновились инструкции обработки контекста. Проверьте публичный `/api/equipment/similar`, затем загрузите фото в осмотре. При развёртывании только обновлённого кода без CPU-процесса поиск будет недоступен, остальные функции сохраняются.

## Проверки

```sh
.venv-visual/bin/python -m unittest discover -s tests -p test_visual_search.py -v
node tests/browser/visual-search-smoke.cjs
node tests/browser/visual-rag-smoke.cjs
```

Браузерный прогон требует работающие CPU-процесс и веб на `127.0.0.1:18012` либо адрес в `CYBER102_VISUAL_ORIGIN`, а также Playwright Chromium/WebKit. Проверяет настоящий поиск, ссылки, сохранение выбранного номера, мобильную ширину и отклонение запоздавшего ответа предыдущего фото.
