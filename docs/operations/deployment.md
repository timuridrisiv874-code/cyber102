# Развёртывание Cyber102 на Windows

Стенд Cyber102 размещается на Windows 11 Pro с RTX 3090 Ti и 24 ГБ видеопамяти. Python обслуживает приложение и SQLite на `127.0.0.1:8102`. Caddy отдаёт перечисленные в `deploy/Caddyfile` публичные файлы JavaScript и CSS напрямую из `C:\cyber102\web`. Запросы HTML-страниц и API он передаёт в Python. При скачивании APK Caddy проверяет пароль команды. Адрес стенда для команды — `https://cyber102.94.41.87.102.sslip.io/`. Имя разрешается в `94.41.87.102`. Для проверки доступа откройте `/index.html` и `/api/health` в новом сеансе без авторизации. Оба адреса должны дать `200`, а загрузка APK — `401`.

Веб-стенд и его API доступны через интернет без пароля. Посетители могут читать материалы организаторов и общий журнал, запускать анализ снимков и видео и сохранять осмотры. На заводе веб-интерфейс, API, SQLite и компьютерное зрение размещаются во внутренней сети предприятия. Диагностический экран рассчитывает правила по демонстрационным наблюдениям и записывает осмотры в SQLite. Экран «Осмотр камерой» использует заранее заданные ответы для встроенных примеров. Снимок с камеры после нажатия кнопки отправляется на сервер для локального анализа. Через внешний HTTPS подтверждены ответы `/analyze` на двух фото насосов и пустом кадре. Камеру на физических телефонах ещё предстоит проверить. [Результаты проверки распознавания](../architecture/vision.md)

## Службы и файлы

| Компонент | Настройка |
| --- | --- |
| Каталог приложения | `C:\cyber102` |
| Python | 3.11, отдельная копия интерпретатора и стандартной библиотеки в `C:\cyber102\runtime`, окружение `C:\cyber102\.venv`. Зависимости можно установить из `C:\cyber102\wheelhouse` без доступа к PyPI. |
| Запуск | Задание `Cyber102Web` в Планировщике заданий. Работает от `LOCAL SERVICE`, запускается при старте Windows, повторяет запуск через минуту после сбоя до 20 раз. |
| Компьютерное зрение | `Cyber102InternVL` запускает выбранную локальную VLM от `fatik` на `127.0.0.1:11436`. Общий с вебом файл `C:\cyber102\var\vlm-model.txt` содержит `qwen3_vl_4b` (выбранный кандидат) или `internvl3_5`. Журнал — `C:\cyber102\var\internvl-worker.log`. Прежнее задание Ollama `Cyber102Vision` на порту `11435` остановлено и отключено; возврат выполняется явно. |
| Python API | `http://127.0.0.1:8102/api/health` на сервере. |
| Caddy | Служба `Elektro62Web`, Caddy 2.11.9. Файл `C:\elektro62\caddy\Caddyfile` импортирует `C:/cyber102/deploy/Caddyfile`. |
| SQLite и журнал | `C:\cyber102\var\cyber102.sqlite3`, `C:\cyber102\var\server.log`. |
| Исходные изображения | `C:\cyber102\data\raw`. На сервер переданы 27 фотографий, SHA-256 каждой сверена с исходным файлом. |
| Загрузка APK | Имя пользователя `cyber102`. Пароль передаётся отдельно. На сервере `C:\cyber102\private\auth.caddy` содержит строку учётной записи с хешем bcrypt. |

Для скачивания APK передайте пароль тестировщику отдельно. Учётные данные и файл `private/auth.caddy` хранятся вне Git. Caddy хранит хеш, принимает учётные данные через HTTPS и удаляет заголовок `Authorization` перед проксированием к Python. [Документация Caddy по Basic Auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth)

Для прямого HTTPS по IP сертификат был выпущен, но проверка подключения выявила сбой выбора сертификата без имени SNI. Доменное имя позволяет браузеру передать SNI, а Caddy — выбрать сертификат отдельного сайта Cyber102. Вход по `http://94.41.87.102/` перенаправляется на доменный HTTPS-адрес. `--public-url` в `deploy/run.py` использует то же имя для печати QR. [Автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https)

## Установка и обновление

Если после перезапуска веб открывается, а анализ временно недоступен, проверьте готовность модели по `http://127.0.0.1:11436/health` на сервере. При завершении задания `Cyber102InternVL` смотрите `var/internvl-worker.log` и системные события Windows в момент старта. На стенде 14 ноября во время неудачной загрузки модели Windows зарегистрировала исчерпание виртуальной памяти (Resource-Exhaustion-Detector, событие 2004). После возврата к рабочей конфигурации проверены отдельный снимок и видео через публичную очередь.

Обновление выполняется наложением проверенного списка файлов. Коллега отдельно поддерживает Android-модуль `web/offline.js`; его версия и совместимые проверки в общем веб-коде сохранены при объединении веток. Сам модуль, Android и APK в этот пакет серверного обновления не входят. Не применяйте очистку или зеркалирование каталога `web`: существующий `offline.js` должен остаться без изменения.

1. Скопируйте файлы выбранной ревизии в `C:\cyber102`. При обновлении сохраните каталоги `runtime`, `.venv`, `.venv-internvl`, `models`, `wheelhouse`, `var`, `private`. Файл `var/vision-backend.txt` сохраняет выбранную модель. Резервная копия SQLite нужна для сохранения истории между развёртываниями.
2. Подготовьте `C:\cyber102\private\auth.caddy` с именем пользователя и хешем пароля для скачивания APK. Ограничьте доступ к нему учётной записью службы Caddy и администраторами. Для первичной установки используйте Python 3.11 по пути из `deploy/install-windows.ps1`. Скрипт копирует интерпретатор и стандартную библиотеку в `runtime`, чтобы `LOCAL SERVICE` мог запускать приложение. При недоступном серверном прокси скачайте совместимые колёса из `requirements.txt` в доступной сети и передайте их в `wheelhouse`.
3. Выполните из PowerShell с правами администратора `C:\cyber102\deploy\install-windows.ps1`. Скрипт установит зависимости веб-приложения, запустит тесты, зарегистрирует задание и проверит ответ Python на порту `8102`. Проверка `/api/health` подтверждает готовность веб-API; готовность модели проверяется отдельно. При первой установке подготовьте окружение и веса по [инструкции GPU-процесса](../../vision_runtime/README.md), выполните `deploy/install-internvl.ps1`, проверьте `/health` на `11436` и реальный запрос `/analyze`. Установщик веб-приложения не загружает модель.
4. Скрипт проверит конфигурацию Caddy до обновления, сохранит её копию `Caddyfile.before-cyber102-*` и применит новую конфигурацию. Если перезагрузка конфигурации завершается ошибкой, скрипт восстанавливает сохранённый файл. После успешной перезагрузки отдельно проверьте HTTPS и сертификат с ноутбука.

Проверка на сервере в PowerShell

```powershell
Get-ScheduledTask -TaskName Cyber102Web | Select-Object TaskName,State
Get-Service Elektro62Web
Invoke-RestMethod http://127.0.0.1:8102/api/health
Get-Content C:\cyber102\var\server.log -Tail 30
```

## Проверка с ноутбука и телефонов

1. **Ноутбук.** Откройте `https://cyber102.94.41.87.102.sslip.io/` в браузере. Убедитесь, что сертификат доверенный, открывается страница осмотра без запроса пароля. Проверьте диагностику, добавьте пробную заметку и нажмите «Сохранить осмотр». После обновления страницы проверьте, что запись осталась в «Истории осмотров».
2. **iPhone.** Откройте тот же HTTPS-адрес в Safari. Можно также сканировать QR насоса штатной камерой. Перейдите в «Осмотр», разрешите доступ к камере, снимите кадр и нажмите «Проверить кадр». Проверьте предпросмотр, рамку и карточку узла. Вернитесь к диагностике и проверьте запись, сохранённую на ноутбуке.
3. **Android.** Сначала повторите шаги в Chrome. Затем откройте тот же адрес в оболочке WebView, если сборка доступна. При скачивании сборки введите пароль команды. В WebView проверьте разрешения Android и страницы на видеозахват. Повторите вход и проверку камеры, карточки и общей истории. На обоих телефонах дополнительно откройте `/index.html`, выберите «Видеопроверка», начните и остановите анализ; убедитесь, что живая камера и последний проверенный кадр разделены. При уходе приложения в фон камера должна отключаться. [Запрос HTTP-аутентификации в WebView](https://developer.android.com/reference/android/webkit/WebViewClient#onReceivedHttpAuthRequest(android.webkit.WebView,android.webkit.HttpAuthHandler,java.lang.String,java.lang.String)) · [Разрешение доступа к камере](https://developer.android.com/reference/android/webkit/WebChromeClient#onPermissionRequest(android.webkit.PermissionRequest))

Если `api/health` отвечает на сервере, а браузер сообщает об ошибке TLS или подключении, проверьте журнал `Elektro62Web`, выпуск сертификата и доступ к HTTPS с сети устройства. Сценарий демонстрации описан в [документе первого чекпоинта](../checkpoints/checkpoint-1.md), структура базы — в [документе по SQLite](../architecture/database.md).

## Текущий сетевой режим

По решению команды сервер с 3090 сейчас удалённый. Телефон передаёт кадр по HTTPS на `94.41.87.102`; модель работает на этом сервере и не вызывает облачные API. Внешние исходящие соединения процессов Python заблокированы [правилами Firewall](../../deploy/lock-inference-network.ps1). Встроенная видеопроверка отправляет отдельные снимки с интервалом, аудио не захватывает. Полностью локальный Wi‑Fi на площадке — [следующий этап](local-network.md), а не условие текущего показа.
