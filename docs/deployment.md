# Развёртывание Cyber102 на Windows

Стенд Cyber102 размещается на Windows 11 Pro с RTX 3090 Ti и 24 ГБ видеопамяти. Python обслуживает приложение и SQLite на `127.0.0.1:8102`. Существующая служба Caddy принимает HTTPS-запросы, проверяет пароль и передаёт запросы Python. Адрес стенда для команды — `https://cyber102.94.41.87.102.sslip.io/`. Имя разрешается в `94.41.87.102`. С ноутбука подтверждён доверенный сертификат, ответ `401` без входа и `200` после входа на `/api/health`, `/api/scenarios`, `/api/history` и `/api/qr`.

Стенд доступен через интернет по паролю и предназначен для демонстрационных данных. На заводе веб-интерфейс, API, SQLite и компьютерное зрение размещаются во внутренней сети предприятия. Диагностический экран рассчитывает правила по демонстрационным наблюдениям и записывает осмотры в SQLite. Экран «Осмотр камерой» использует заранее заданные ответы для встроенных примеров. Снимок с камеры после нажатия кнопки отправляется на сервер для локального анализа. Через внешний HTTPS подтверждены ответы `/analyze` на двух фото насосов и пустом кадре. Камеру на физических телефонах ещё предстоит проверить. [Результаты проверки распознавания](vision.md)

## Службы и файлы

| Компонент | Настройка |
| --- | --- |
| Каталог приложения | `C:\cyber102` |
| Python | 3.11, отдельная копия интерпретатора и стандартной библиотеки в `C:\cyber102\runtime`, окружение `C:\cyber102\.venv`. Зависимости можно установить из `C:\cyber102\wheelhouse` без доступа к PyPI. |
| Запуск | Задание `Cyber102Web` в Планировщике заданий. Работает от `LOCAL SERVICE`, запускается при старте Windows, повторяет запуск через минуту после сбоя до 20 раз. |
| Компьютерное зрение | Задание `Cyber102Vision` запускает локальный Ollama от `fatik` на `127.0.0.1:11435`. Журнал — `C:\cyber102\var\vision.log`. |
| Python API | `http://127.0.0.1:8102/api/health` на сервере. |
| Caddy | Служба `Elektro62Web`, Caddy 2.11.9. Файл `C:\elektro62\caddy\Caddyfile` импортирует `C:/cyber102/deploy/Caddyfile`. |
| SQLite и журнал | `C:\cyber102\var\cyber102.sqlite3`, `C:\cyber102\var\server.log`. |
| Исходные изображения | `C:\cyber102\data\raw`. На сервер переданы 27 фотографий, SHA-256 каждой сверена с исходным файлом. |
| Вход | Имя пользователя `cyber102`. Пароль передаётся отдельно. На сервере `C:\cyber102\private\auth.caddy` содержит строку учётной записи с хешем bcrypt. |

Пароль для команды хранится на ноутбуке в игнорируемом файле `var/deploy-access.json`. Пароль и файл `private/auth.caddy` остаются вне Git. Caddy хранит хеш, принимает учётные данные через HTTPS и удаляет заголовок `Authorization` перед проксированием к Python. [Документация Caddy по Basic Auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth)

Для прямого HTTPS по IP сертификат был выпущен, но проверка подключения выявила сбой выбора сертификата без имени SNI. Доменное имя позволяет браузеру передать SNI, а Caddy — выбрать сертификат отдельного сайта Cyber102. Вход по `http://94.41.87.102/` перенаправляется на доменный HTTPS-адрес. `--public-url` в `deploy/run.py` использует то же имя для печати QR. [Автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https)

## Установка и обновление

1. Скопируйте файлы выбранной ревизии в `C:\cyber102`. При обновлении сохраните каталоги `runtime`, `.venv`, `wheelhouse`, `var`, `private`. Резервная копия SQLite нужна для сохранения истории между развёртываниями.
2. Подготовьте `C:\cyber102\private\auth.caddy` с именем пользователя и хешем пароля. Ограничьте доступ к нему учётной записью службы Caddy и администраторами. Для первичной установки используйте Python 3.11 по пути из `deploy/install-windows.ps1`. Скрипт копирует интерпретатор и стандартную библиотеку в `runtime`, чтобы `LOCAL SERVICE` мог запускать приложение. При недоступном серверном прокси скачайте совместимые колёса из `requirements.txt` в доступной сети и передайте их в `wheelhouse`.
3. Выполните из PowerShell с правами администратора `C:\cyber102\deploy\install-windows.ps1`. Скрипт установит зависимости, запустит тесты, зарегистрирует задание и проверит ответ Python на порту `8102`.
4. Скрипт проверит конфигурацию Caddy до обновления, сохранит её копию `Caddyfile.before-cyber102-*` и применит новую конфигурацию. Если перезагрузка конфигурации завершается ошибкой, скрипт восстанавливает сохранённый файл. После успешной перезагрузки отдельно проверьте HTTPS и сертификат с ноутбука.

Проверка на сервере в PowerShell

```powershell
Get-ScheduledTask -TaskName Cyber102Web | Select-Object TaskName,State
Get-Service Elektro62Web
Invoke-RestMethod http://127.0.0.1:8102/api/health
Get-Content C:\cyber102\var\server.log -Tail 30
```

## Проверка с ноутбука и телефонов

1. **Ноутбук.** Откройте `https://cyber102.94.41.87.102.sslip.io/` в браузере. Убедитесь, что сертификат доверенный, появляется запрос на вход и после ввода пароля открывается паспорт `P-102`. Проверьте диагностику, добавьте пробную заметку и нажмите «Сохранить осмотр». После обновления страницы проверьте, что запись осталась в «Истории осмотров».
2. **iPhone.** Откройте тот же HTTPS-адрес в Safari. Можно также сканировать QR насоса штатной камерой. Авторизуйтесь, перейдите в «Осмотр камерой», разрешите доступ к камере, снимите кадр и нажмите «Проверить кадр». Проверьте предпросмотр, рамку и карточку узла. Вернитесь к диагностике и проверьте запись, сохранённую на ноутбуке.
3. **Android.** Сначала повторите шаги в Chrome. Затем откройте тот же адрес в оболочке WebView, если сборка доступна. WebView должен обрабатывать запрос логина через `onReceivedHttpAuthRequest`, а также разрешения Android и страницы на видеозахват. Повторите вход и проверку камеры, карточки и общей истории. [Запрос HTTP-аутентификации в WebView](https://developer.android.com/reference/android/webkit/WebViewClient#onReceivedHttpAuthRequest(android.webkit.WebView,android.webkit.HttpAuthHandler,java.lang.String,java.lang.String)) · [Разрешение доступа к камере](https://developer.android.com/reference/android/webkit/WebChromeClient#onPermissionRequest(android.webkit.PermissionRequest))

Если `api/health` отвечает на сервере, а браузер сообщает об ошибке TLS или подключении, проверьте журнал `Elektro62Web`, выпуск сертификата и доступ к HTTPS с сети устройства. Сценарий демонстрации описан в [документе первого чекпоинта](checkpoint-1.md), структура базы — в [документе по SQLite](database.md).
