# Данные и модели диагностики насоса Cyber102

За два дня можно показать два независимых результата. Первый — локальная проверка двенадцати инженерных правил на входных признаках с объяснением, подсветкой узла и сохранением осмотра. Второй — эксперимент с обучаемой моделью на размеченных измерениях реального стенда. Обе части используют разные источники меток. Диагностические сценарии из SQLite годятся для проверки логики и интерфейса. Для обучения и оценки нужны независимые наблюдения с известным состоянием оборудования.

Первый эксперимент CatBoost на UCI завершён. Accuracy на отложенных циклах составила 53,1%, а все 123 случая сильной внутренней утечки модель отнесла к слабым. Экспериментальный артефакт хранится отдельно от сервера диагностики. [Методика и результаты CatBoost](benchmark-uci.md)

## AutoGluon и CatBoost

**CatBoost** — библиотека градиентного бустинга для классификации и регрессии с числовыми и категориальными признаками. Для одного табличного эксперимента достаточно отдельного окружения Python 3.11 и модели `CatBoostClassifier`. Официальные колёса поддерживают Windows x86-64 с CUDA. Для небольшого набора начните с CPU. На RTX 3090 Ti можно отдельно сравнить время обучения с `task_type="GPU"`. GPU-обучение CatBoost может давать немного различающиеся результаты между запусками. Код библиотеки — Apache 2.0. [Репозиторий CatBoost](https://github.com/catboost/catboost) · [Установка Python](https://catboost.ai/docs/en/installation/python-installation-method-pip-install) · [Обучение на GPU](https://catboost.ai/docs/en/features/training-on-gpu)

**AutoGluon** — набор инструментов AutoML под Apache 2.0. `TabularPredictor` сравнивает модели и может строить ансамбль. CatBoost доступен в нём как семейство `CAT`. `TimeSeriesPredictor` решает задачу прогноза рядов. Для распознавания объектов и изображений есть отдельный модуль AutoMM со своими зависимостями. Начните с сравнения табличных моделей в `autogluon.tabular`, если успеете повторить тот же разрез данных и метрики. AutoGluon документирует обучение на CPU и GPU под Windows. WSL2 с CUDA может пригодиться для зависимостей AutoMM. Доступ к GPU и версии пакетов проверяйте в отдельном окружении от веб-сервера. [Репозиторий AutoGluon](https://github.com/autogluon/autogluon) · [Поддерживаемые модели TabularPredictor](https://auto.gluon.ai/stable/api/autogluon.tabular.TabularPredictor.fit.html) · [Установка AutoGluon](https://auto.gluon.ai/stable/install.html) · [CUDA в WSL2](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)

В итоговом интерфейсе показывайте раздельно сработавшие правила и оценку модели, когда она появится. Для CV храните наблюдение, зону кадра и уверенность модели, если она выдаётся. Для телеметрии храните окно наблюдений, признаки и версию модели. Диагностика по правилам получает признаки от этих модулей и соотносит их с паспортом и нормами.

## План на два дня

1. **День 1.** Оставить 14 синтетических сценариев для проверки движка правил и интерфейса. Отдельно подготовить по одной строке признаков на цикл UCI. Начать с простых агрегатов давления, расхода, температуры, вибрации и мощности. Для `CatBoostClassifier` использовать метку внутренней утечки из третьего столбца `profile.txt`. Исключить из входов все метки, вычисленные по ним поля и идентификатор цикла.
2. **День 2.** Оценить CatBoost на отложенных группах опытов или последовательных блоках циклов с представленностью нужных классов. Не смешивать соседние окна одного прогона между обучением и тестом. Зафиксировать состав разреза, количество примеров по классам, матрицу ошибок, macro-F1 и полноту редких классов. При наличии времени повторить эксперимент с AutoGluon на том же разрезе и том же наборе метрик. Результат характеризует только выбранный стенд.
3. **Параллельно.** Собрать свою небольшую фотосерию с разрешением на использование. Разделить фото по сессиям съёмки или экземплярам насоса. Снимать видимые признаки при разных ракурсах и освещении. Для внешних файлов фиксировать ссылку, автора, версию и лицензию. В рабочем контуре хранить исходные файлы и проверочные кадры, в репозитории — код, описание происхождения данных и синтетические примеры.

Для заводского обучения запросите фотографии и телеметрию, привязанные к серийному номеру и времени, подтверждение дефекта инженером, режим работы, расположение датчиков, единицы и регламент конкретного насоса. Для прогноза остаточного ресурса дополнительно нужны истории наработки, обслуживания и замен. Без этих данных показатель качества на открытом стенде нельзя переносить на оборудование завода.
