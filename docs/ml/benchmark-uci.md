# CatBoost на открытом гидравлическом стенде UCI

Этот эксперимент проверяет, может ли CatBoost различить три степени внутренней утечки насоса по показаниям датчиков в одном лабораторном стенде. Использовали набор *Condition monitoring of hydraulic systems* Николая Хельвига, Элисео Пиньянелли и Андреаса Шютце, DOI 10.24432/C5CW21. Набор содержит 2 205 циклов длительностью 60 секунд и распространяется по CC BY 4.0. [Карточка UCI](https://archive.ics.uci.edu/dataset/447/condition+monitoring+of+hydraulic+systems) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

Метка взята из третьего столбца файла `profile.txt`. Значения 0, 1 и 2 означают отсутствие, слабую и сильную внутреннюю утечку соответственно. Для каждого цикла рассчитали 112 признаков по 14 каналам давления, мощности двигателя, расхода, температуры и вибрации. Для каждого канала это среднее, стандартное отклонение, минимум, максимум, 5-й, 50-й и 95-й процентили и разность средних за последние и первые пять секунд. Расчёт использует весь цикл, поэтому результат доступен после его завершения. Столбцы профиля и индекс цикла в признаки не входят.

Модель обучалась на первых 1 323 циклах. Следующие 441 использовались для ранней остановки, последние 441 — для теста. Разбиение следует порядку циклов в архиве. Даты и идентификаторы отдельных насосов в наборе отсутствуют.

| Часть выборки | Циклы | Без утечки | Слабая | Сильная |
| --- | --- | ---: | ---: | ---: |
| Обучение | 1–1323 | 749 | 287 | 287 |
| Валидация | 1324–1764 | 277 | 82 | 82 |
| Тест | 1765–2205 | 195 | 123 | 123 |

## Результат

Модель обучена на CPU в CatBoost 1.2.10. Ранняя остановка сохранила 98 деревьев. Базовый классификатор всегда выбирает самый частый класс обучающей части, «без утечки».

| Модель и выборка | Accuracy | Macro F1 | Balanced accuracy |
| --- | ---: | ---: | ---: |
| CatBoost, валидация | 83,0% | 0,723 | 69,5% |
| CatBoost, тест | 53,1% | 0,365 | 43,9% |
| Частый класс, тест | 44,2% | 0,204 | 33,3% |

| Фактический класс на тесте | Предсказано без утечки | Предсказана слабая | Предсказана сильная |
| --- | ---: | ---: | ---: |
| Без утечки | 195 | 0 | 0 |
| Слабая утечка | 84 | 39 | 0 |
| Сильная утечка | 0 | 123 | 0 |

На тесте модель распознала 39 из 123 слабых утечек и отнесла все 123 сильные утечки к слабым. Результат существенно ниже валидационного. При таком результате модель не подходит для определения серьёзности утечки в эксплуатации.

Эксперимент оценивает перенос между частями записей одного стенда. Условия испытаний и соседние циклы могут быть похожи. Для оценки переноса на другие агрегаты нужны полевые данные и разбиение по оборудованию. Внутренняя утечка в этом наборе отличается от видимой утечки торцевого уплотнения на экране Cyber102. Артефакт остаётся в каталоге эксперимента. Сервер диагностики его не загружает.

## Как повторить

Из корня репозитория выполните команды с отдельным окружением Python 3.10–3.13.

```sh
mkdir -p data/raw/uci_hydraulic
curl -fL 'https://archive.ics.uci.edu/static/public/447/condition+monitoring+of+hydraulic+systems.zip' \
  -o data/raw/uci_hydraulic/uci-hydraulic.zip
python -m pip install -r ml/requirements-catboost.txt
python -m ml.benchmark_uci --archive data/raw/uci_hydraulic/uci-hydraulic.zip --output ml/artifacts/uci
```

SHA-256 использованного архива: `24128aad2ee45eea7e6b63ebbd9992cdf25d0483a2cebefbfc13bc69079af1f2`.

Команда сохраняет модель `uci-internal-leakage.cbm` и отчёт `report.json` в новый каталог. Обучение использует CPU с двумя потоками. Укажите новый каталог при повторном прогоне.

## Сравнение AutoGluon и расширенных признаков, 13 ноября 2026

Четыре заранее заданных эксперимента обучены на том же архиве и разбиении 1323/441/441. Использован реальный управляемый дефект стенда из `profile.txt`, а не метка, вычисленная из порогов входных измерений. Финальные 441 цикла уже участвовали в предыдущем отчёте, поэтому это повторное использование известного теста, а не новая слепая проверка. Настройки после просмотра результатов не менялись. [Полный отчёт](uci-autogluon-report.json) · [Код эксперимента](../../ml/benchmark_uci_autogluon.py)

Расширенный набор содержит 340 признаков: прежние 112, ещё по 15 характеристик формы каждого из 14 сигналов и 18 характеристик связей между заранее выбранными парами датчиков. Добавлены RMS, размах, межквартильный размах, медианное абсолютное отклонение, асимметрия, эксцесс, средняя величина соседних изменений, тренд, корреляция соседних отсчётов и среднее со стандартным отклонением для трёх частей цикла. Между каналами считаются корреляция средних за секунду, разность и отношение средних. Всё рассчитывается внутри текущего законченного цикла. Другие неисправности из профиля, флаг стабильности и номер цикла в признаки не входят.

CatBoost ограничен 500 деревьями глубины 5 и ранней остановкой. AutoGluon 1.6.1 сравнивает CatBoost и Random Forest, затем строит взвешенный ансамбль по валидационному `log_loss`; случайный бэггинг и стекинг отключены. Обучение шло последовательно на 4 CPU, без GPU; AutoGluon получил до 300 секунд и мягкий лимит 4 ГБ на вариант. Начальный CatBoost точно воспроизвёл прежние 98 деревьев и тестовую матрицу ошибок.

| Вариант | Признаки | Обучение, с | Accuracy | Balanced accuracy | Macro F1 | Log loss ↓ | Найдено сильных утечек |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| CatBoost | 112 | 0,73 | 53,1% | 43,9% | 0,365 | 0,787 | 0 / 123 |
| AutoGluon | 112 | 5,48 | 48,1% | 37,9% | 0,310 | 0,626 | 2 / 123 |
| CatBoost | 340 | 1,98 | 72,8% | 67,5% | 0,584 | 0,479 | 6 / 123 |
| AutoGluon | 340 | 8,03 | 64,4% | 57,5% | 0,535 | 0,477 | 17 / 123 |

Главный выигрыш в этом опыте дали признаки. По валидационному `log_loss` лучший из четырёх вариантов — CatBoost на 340 признаках: 0,228 против 0,235 у AutoGluon на 340. На тесте AutoGluon немного лучше по ошибке вероятностей, CatBoost лучше по точности классов. Сильная утечка часто принимается за слабую; даже лучший показатель её обнаружения составляет лишь 17 из 123. Ни один вариант не подключён к эксплуатационной диагностике.

Извлечение признаков заняло 5,86 с. Пиковая память всего процесса, включая извлечение и все четыре варианта, — 1,21 ГБ; это не отдельный замер памяти каждой модели. Сохранённые модели повторно загружены, и их прогнозы воспроизвели исходные метрики на всех 441 тестовых циклах без переобучения.

### Использовать готовый CatBoost без обучения

В рабочей копии завершённый запуск находится в `var/automl-comparison/uci-four-arm-v1/`. Модель `catboost_enhanced/model.cbm` содержит 78 деревьев и ожидает 340 именованных признаков. Рядом сохранены `features.npz`, `report.json` и `serialization-check.json`. Каталог `var/` исключён из Git: в свежем клоне эти локальные артефакты отсутствуют; опубликованный отчёт находится в [uci-autogluon-report.json](uci-autogluon-report.json).

Из корня этой рабочей копии можно повторить проверку готовой модели на сохранённом тесте, не вызывая обучение:

```sh
.venv-automl/bin/python - <<'PY'
import json
from pathlib import Path
import numpy as np
from catboost import CatBoostClassifier, Pool
from ml.benchmark_uci_autogluon import metrics

run = Path('var/automl-comparison/uci-four-arm-v1')
model = CatBoostClassifier()
model.load_model(str(run / 'catboost_enhanced/model.cbm'))
with np.load(run / 'features.npz', allow_pickle=False) as saved:
    names = saved['names'].tolist()
    test = saved['enhanced'][1764:]
    labels = saved['leakage'][1764:]
assert names == model.feature_names_
probabilities = model.predict_proba(Pool(test, feature_names=names))
result = metrics(labels, probabilities, np)
report = json.loads((run / 'report.json').read_text())
assert result == report['arms']['catboost_enhanced']['metrics']['test']
print(json.dumps(result, ensure_ascii=False, indent=2))
PY
```

Проверка выполнена 13 ноября 2026: имена всех 340 признаков совпали, результат имел форму `441 × 3`, метрики точно совпали с локальным и опубликованным отчётами. SHA-256 модели: `57aa5f49785b2e6d02a1ebdf8b0faccaea6a8c9de896839b28904fb305032ad3`.

Для нового входа нужны законченные 60-секундные сигналы тех же 14 каналов с теми же единицами, частотами и порядком расчёта признаков. Одна строка текущих показаний Cyber102 не заменяет такой цикл. Готового серверного адаптера для этих сигналов нет: `server/assessment.py` вызывает правила, а не эту модель. `runtimeReady: false` в отчёте обозначает эту границу применения, а не незавершённое обучение.

### Созданные данные и проверка чувствительности

Подготовлен архив `cyber102-uci-hydraulic-features-v1.zip`: реальные `train.csv`, `validation.csv`, `test.csv` и три искусственно изменённых варианта тех же тестовых строк. В таблицах отдельно записаны номер исходного цикла, часть выборки, происхождение и исходная метка утечки; эти поля нельзя подавать модели как признаки. Архив содержит список признаков, контрольные суммы, описание преобразований, авторство UCI и лицензию CC BY 4.0.

Для шума к признакам добавлен независимый Gaussian-шум с масштабом 0,10 стандартного отклонения обучающей части. Для отсутствия PS1 все признаки с его участием заменены пропусками. Для дрейфа к ним добавлено 0,50 обучающего стандартного отклонения. Seed зафиксирован: 20261113. Метки сохранены от реальных циклов. Это проверка численной чувствительности в пространстве признаков, а не моделирование физической поломки; эти строки используются только для оценки.

| Вариант | Исходный тест | Шум | PS1 отсутствует | Дрейф PS1 |
| --- | ---: | ---: | ---: | ---: |
| CatBoost, 112 | 43,9% | 64,8% | 43,9% | 43,9% |
| AutoGluon, 112 | 37,9% | 59,3% | 82,1% | 38,2% |
| CatBoost, 340 | 67,5% | 71,1% | 66,1% | 64,8% |
| AutoGluon, 340 | 57,5% | 66,9% | 57,2% | 55,3% |

В таблице приведена balanced accuracy. Её рост после искусственного изменения не доказывает улучшения диагностики: у AutoGluon на 112 признаках удаление PS1 резко меняет решение. Дрейф PS1 снижает обнаружение сильной утечки до 0 из 123 для CatBoost на 340 признаках и до 1 из 123 для AutoGluon на 340. Это основание исследовать устойчивость на новых данных, а не подбирать преобразования по уже просмотренному тесту.

### Повторить четыре эксперимента

```sh
python -m pip install -r ml/requirements-autogluon.txt
python -m ml.benchmark_uci_autogluon \
  --archive data/raw/uci_hydraulic/uci-hydraulic.zip \
  --output var/automl-comparison/new-run --cpus 4 --time-limit 300 --memory-gb 4
```

Перед обучением сохраняются протокол `preregistered.json`, снимок исполняемого кода и таблицы признаков. Каждый из четырёх вариантов получает свой каталог модели; результаты и происхождение сохраняются в `report.json`. Для изменения состава признаков или параметров нужен новый эксперимент и новая независимая оценка.
