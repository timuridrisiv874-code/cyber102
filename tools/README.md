# Сборка инженерного пакета

Инструменты этой папки работают с документацией отдельно от сервера. Рабочий интерфейс и базы не изменяются. Секреты и исходные заводские данные не включаются в архив.

## Состав

- `build_knowledge_pack.py` создаёт Word из введения, шести глав и библиографии в `docs/research/`; нужны Python с `python-docx`, Node.js и `marked`.
- `tokenize_knowledge.mjs` передаёт токены Markdown сборщику. Путь к `marked.esm.js` можно указать явно.
- `package_knowledge.py` формирует ZIP по разрешённым каталогам, добавляет манифест SHA-256 и проверяет каждое вложение.
- `validate_knowledge.py` проверяет две JSON Schema, примеры, 15 отрицательных случаев, согласованность реестров источников/каталога данных и локальные ссылки.

## Порядок обновления

1. Изменить главу в `docs/research/chapters/` и соответствующий реестр `docs/research/sources/sources-*.json`; синхронизировать `sources/sources.json` и библиографию `sources/README.md`. Вставлять ссылки на первоисточники рядом с утверждениями.
2. Создать отдельное Python-окружение для инструментов. Установить `python-docx` и зависимости `knowledge-requirements.txt`. `jsonschema[format]` нужен для действительной проверки даты и URI.
3. Собрать Word из корня репозитория:

```sh
python tools/build_knowledge_pack.py --node node --marked /путь/к/marked/lib/marked.esm.js
```

4. Конвертировать DOCX в PDF через LibreOffice. Результат должен находиться по `output/pdf/cyber102-engineering-pack.pdf`. При работе в Codex используется выделенный bundled runtime и `render_docx.py --emit_pdf` из Documents skill.
5. Просмотреть все страницы полученного PDF, проверить переносы, таблицы и ссылки. После исправлений пересобрать и повторить визуальную проверку.
6. Упаковать и проверить:

```sh
python tools/package_knowledge.py
python tools/validate_knowledge.py
```

ZIP не включает себя; ссылка на ZIP в README предназначена для загрузки из репозитория. Манифест внутри архива содержит пути, размеры и SHA-256 всех остальных вложений.

Валидатор не обращается к интернету, не проверяет физическую достоверность измерений и не импортирует данные в приложение. Ограничения частотных полос, порядок времён и соответствие рамки реальному компоненту описаны как отдельные требования интеграционного этапа.
